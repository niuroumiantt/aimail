# 邮箱切换与阅读布局修复

起点：Aimail `2f0a798143e2e8c7ee45f08ef47bc45785f34ed9`。用户反馈首次加载、Larry / sales 切换慢，希望邮件列表可拖动、收起和自动隐藏。

## 已改动

- 收件列表与邮箱信息优先返回并显示；线索建议、失败计数、线索和推送状态随后加载。选择邮箱立即更新地址，清除旧邮箱内容，并显示加载或错误状态。
- 每个邮箱使用独立 DataSource。过期列表、详情、AI 分析和刷新结果不能写回当前邮箱；重复的在途详情请求合并。发送令牌和实际发送始终使用同一个邮箱作用域，即使用户中途切换。
- 文件数据库的收件列表、详情、邮箱列表、邮箱信息、会话读取使用每请求独立的只读连接和一致快照。收信或模型调用仍在等待时，可以阅读已提交邮件。数据库写入继续使用原来的串行锁，内存数据库也保留旧锁。未删除邮箱权限校验。
- 列表查询不再读取每封信的正文；详情仍按需读取完整邮件。设计预览、跟进、开发信、线索页及组件页按路由加载。
- 正式收件箱支持拖动列表边界、方向键微调、双击或 Home 恢复宽度；支持手动收起、展开以及“阅读时隐藏”。浏览器只保存布局尺寸和偏好，不保存邮件内容。手机保留列表/详情切换。

本批不修改数据库结构、业务阶段、登录方式、邮箱配置、同步游标、通知或发送计划。

## 验证

- 完整 `tools/precommit.sh`：Python 270 项测试及 3 个 subtests；Web 71 项测试；类型、lint、构建和全部守卫。
- 新增文件数据库并发用例：分别暂停模拟 IMAP 同步、AI 分析；在释放网络操作前读取两个授权邮箱的列表和详情，检查未知身份 401、越权邮箱 403、跨邮箱线程 404。没有真实网络、模型或发信。
- 前端用例：慢线索接口不阻挡列表；快速往返切换时旧列表/详情不覆盖；拒绝访问时清除旧数据；发送两步保留原邮箱；拖动替代键盘操作、宽度边界、持久化、恢复、自动隐藏与展开。
- Chromium 人工场景自动验证：1440px 下实际拖动 352 → 462px；收起、展开、刷新持久化及双击恢复；390px 下列表/详情不横向溢出，无页面脚本错误。数据全部来自设计样本。

路由拆分的本地生产构建：入口 JS 由约 1,035.81 kB（gzip 332.30 kB）降至 326.06 kB（gzip 103.38 kB）；另有三个预加载共享模块共约 70.13 kB。该对比不包含字体、CSS 或实际网络延迟。

这些验证证明修改的行为，不能代替生产浏览器的延迟测量。用户当时截图中的 73 条邮件未复制到云端。

## 上线与验收

沿用现有 main → CI → SHA Release → Aimail updater。合并前后必须核对 CI 和正式资产；不手工覆盖整个 Compose、不重复切换已运行版本。

运行服务器只可通过 M5 的既有 `ssh aliyun` 访问；当前云环境没有该 SSH 配置。本记录不声明生产版本已验收。M5 后续只读核对：

1. `/srv/aimail-deploy/current.json`、实际容器镜像 revision 与本批最终主干 SHA 一致；若 updater 正在下载，先观察现有执行。
2. updater 记录的升级前 SQLite 一致备份存在，健康检查通过；Authentik、邮箱配置和同步状态保留。
3. 登录 Larry 后切换 Larry / sales，分别记录 `/api/mailbox`、`/api/threads` 的耗时。切换立即更新地址，无旧邮箱邮件短暂回流；快速切回没有串数据。
4. 在现有收信或 AI 分析进行时浏览另一封已保存的信；不为验收发送真实邮件、重放通知或清空游标。
5. 拖动、双击恢复、手动收起、自动隐藏、展开及刷新后保留偏好；手机返回列表正常。
6. 使用既有低权限人员账号复核不可查看未授权邮箱，不能从 URL 猜测其他邮箱线程。

如需回退，用现有部署器和保留镜像；本批没有 schema 迁移，不用旧备份覆盖上线后的邮件写入。
