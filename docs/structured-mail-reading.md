# 结构化邮件阅读（本地第一阶段）

每封邮件入库后进入 `mail_fact_reading` 持久队列，不依赖用户点击。
本地服务经原有独立 API 网关执行 `extract_mail_facts@1`；网关保留请求、响应、token、耗时。
原始邮件不改动，输出是待核对建议，不写入已确认 lead。

## 当前已覆盖

- 新增正文、邮件头；沿用入库的引用历史切分，不发送 `body_quoted`。
- 按当前任务版本、同邮箱和相同输入哈希复用结果；成功的邮件不重复提取。
- 全部字段必须具有连续原文引用，value 必须包含于引用，引用必须包含于输入。
- 公司、联系人、邮箱、国家、城市、职位、产品、型号、数量、价格、币种、交期、贸易条款、付款条件、客户要求、我方承诺、下一步。
- 阅读区顶部固定两行。长值省略，点击展开完整值和原文；窄屏两行可横向滚动。
- 单任务串行。出错自动暂停，用户可在顶部状态中恢复和重试；暂停状态跨重启保留。
- 启动回收中断任务，新入库邮件自动补入队列。摘要仍由原有按钮按需生成。

## 尚未覆盖，不应宣称全部邮件已读完

- 网易同步仍为手动触发，INBOX 最近 30 天、每次最多 30 封、单封上限 2 MB。
- 这个提取任务尚不处理附件，不从引用历史补齐字段；异常引用格式仍可能被保留为新增正文。
- 尚未实现跨邮件实体归并、历史结构化上下文继承、变更事件和完整话题快照。
- 问邮箱仍是现有正文证据问答，尚未切换为数据库统计/检索。
- 48,000 字符以上输入显式失败，不截断后冒充已完整提取。
- 每次提取输出上限 3,072 tokens；输出达到上限即失败，不把截断 JSON 当结果。
- 本地客户端等待上限为 610 秒，长于现有网关 600 秒；失败后暂停批量队列。
- 精确摘录校验防止杜撰值，但不能证明语义分类完全正确；仍需人工核对。

## 验证

`evals/extract_mail_facts/run.py` 是原文约束检查，加 `--live` 使用配置的真实模型测试。
首次本机 API 实测通过两个样本（明确事实与注入指令），不是完整业务准确率评估。
测试还覆盖原文保持、引用历史排除、成功结果幂等和失败显形。
