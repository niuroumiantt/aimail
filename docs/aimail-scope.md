# aimail：邮件沟通与销售交接

2026-09-25 用户确认的边界。本文件是目标与验收清单，不是上线声明。

## 责任

- leadsgen 发现公司与联系人，保留采集来源，把待联系对象交给 aimail。
- aimail 负责邮件收发、AI 翻译与阅读、回复建议，以及任何阶段的销售交接。
- sales@glocalstorage.com 只收信；客户沟通从获授权的个人邮箱发出。
- 同一个员工可以读取多个获授权邮箱；读取权限不授予发件身份。
- CRM、正式客户建档、报价和合同以后实施。leadsgen 不承担这些职责。
- OA 保留组织、审批、待办和通知；重复收件箱需核对数据与调用后退役。

## 两条入口

1. leadsgen 采集 → aimail 接收资料并回执 → 人员确认 → 个人邮箱联系。
2. sales 公共收件箱收到询盘 → aimail 分配负责人 → 个人邮箱回复。

导入回执不代表已发送；SMTP 接受不代表客户收到。现有六次开发信序列不能默认
启用，也不能因为改名而触发发送。实际邮件发送仍需明确的用户动作或既有有效授权。

## 会话交接验收

- 任何阶段均可分配或转交给已登记员工，目标不能由未经验证的自由文本身份产生。
- 模型按相关邮件生成阶段总结，保留模型标识、原文出处、未确认事项；模型失败
  明确提示，不伪造成功摘要，不静默丢失长会话内容。
- 接收人获得本次相关会话、历史邮件与附件的权限，不获得整个来源邮箱权限。
- 交接记录保留发起人、接收人、时间、说明、待接手/已接手状态。
- 接手前原负责人继续负责；并发接手或转交不能造成两个有效负责人。
- 回复原负责人邮箱的新邮件仍关联会话并提醒当前负责人。
- 未授权员工不能通过邮件、附件、下载、AI 分析或发件接口绕过会话权限。
- 交接不会自动发送或向外部转发邮件；邮件导出需在受控接口中执行。

## 发件与交接边界

SMTP 不再继承 IMAP 凭据。需要显式设置 SMTP_HOST、SMTP_USER、SMTP_PASSWORD。
实际 SMTP 发件地址必须匹配 SMTP_USER。sales 公共邮箱在构建邮件和 SMTP
投递两层拒绝发信。可信登录模式按员工邮箱选择明确登记的个人通道，不信任
请求正文自报的发件人；有读取共享邮箱权限不等于能以共享邮箱发件。

会话交接候选版新增 /followups 页面与线程级接口：待接手时保留原负责人，
接手后可再次转交；带版本检查、持久审计与原始 EML（含附件）导出。
FOLLOWUP_MEMBERS 必须由运维按已验证员工登记，空值不启用接口。
候选版通过已记录的发信 Message-ID、客户地址和已接手负责人关联跨个人邮箱回复，
不按相同主题跨邮箱归并。任意阶段的完整业务流程仍需真实员工验收，不可称为已交付。
AI 总结覆盖邮件正文，不解析二进制附件；原附件保留在完整 EML 导出中。
长会话超过总结上限明确拒绝，不截断后冒充完整总结。

SSH 已重新验证可用；原公钥失败记录不再是当前阻碍。GitHub 仓库、Python 包、生产镜像、Compose 服务和数据目录已经使用 Aimail 名称；回退兼容物仍保留。阿里云已加入 Tailscale，Spark 模型网关在受限 ACL 下可达。
