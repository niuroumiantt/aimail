# Aimail 统一工作区设计

2026-10-09 最终组件方案已确定：[ADR 0013](adr/0013-unified-owned-ui-components.md)。
全站采用自有组件 + Radix + Tailwind，Lucide 图标；收件箱布局参照用户提供的 Outlook Mac 截图。
Ant Design 逐页迁出；本文件描述的共享主题适配是过渡状态，页面迁移尚未完成。

这次调整直接应用于生产收件箱、线索、跟进、开发信和组件页。公开邮箱产品提供的信息层级和布局启发不等于它们的内部实现；Aimail 不移植其品牌、私有 API 或未经核验的 UI 代码。

统一的设计由中央令牌和共享组件表达，而不是各页面分别选颜色。

- 字体：自托管 Inter / Noto Sans SC；正文 14px，收件箱邮件原文 15px、行高 1.65；辅助信息 12px，栏标题 16px，页面标题 20px。
- 空间：4/8px 间距节奏；导航、列表、阅读区和客户区分别有明确边界与自己的滚动区域。只对需要独立操作的内容使用容器，普通文字不再层层包卡片。
- 颜色：冷白表面、石板灰文字，靛蓝作为唯一常规操作与选中强调；警告和失败色仅表达真实状态。亮暗模式遵循同一语义令牌。
- 图标：Lucide，常用 16/18px、线宽 1.75；图标与文本共同对齐，装饰图标不替代操作名称。组件库内置交互图标由其组件管理。
- 组件：控件圆角 8px、面板圆角 12px；表单、按钮和菜单复用自有组件。现存 Ant Design 控件在迁出前继续读取共享字体、颜色及尺度。

收件箱支持只显示标题的简洁模式以及包含发件人、标题和摘要的概括模式。买卖邮件有清晰的 SALES LEAD 标记，普通邮件使用内容类型。联系人聚拢是可选操作，相同地址的独立交易话题不会合并成一个需求。

收件箱集中搜索位于品牌色顶栏，回复、删除/恢复、同步、AI 阅读和分配位于工具栏。
应用图标栏与邮箱视图分开；联系人优先显示实际发件人，不把 `gmail` 等旧域名占位当成公司。
默认按本地日历的今天、昨天、本周、更早分组，联系人聚拢仍可切换。
列表的单行预览是有署名的 AI 摘要，不声称是原文节选；未核实和识别失败仍明确提示。
现有数据没有可靠的已读/未读字段，因此不绘制虚假的未读圆点，也不展示尚未支持的归档、旗标等操作。
默认列表宽度 360px，拖动及用户保存的宽度仍保留。正文主题和发件信息不重复，来信不再套一层边框卡片。

用户参考线索页卡片后，收件箱的大区域分别独立为面板：邮件工具栏、应用图标栏、邮箱视图、
邮件列表、正文、客户工作区。统一 12px 圆角、轻边框和阴影；桌面面板间隔 12px，手机 8px。
导航使用浅灰底、列表使用偏冷浅色底、原文保持白底、客户区使用淡蓝灰底，暗色模式对应深色表面。
面板角色色集中为 `panel-navigation`、`panel-list`、`panel-context`，不承担业务状态含义。
阅读区宽度预算包含新的面板间距，窄桌面打开客户区时仍保留至少 360px 的阅读面板。

右侧客户工作区保持独立，初次默认收起；用户原有展开/收起偏好仍保留。阅读旧邮件、回复或滚动正文不会改变最新累计需求。
工作区按当前话题展示客户资料和截至最新邮件的统一生意概况；不在右侧重复原文入口、
时间线与单封读数。来源引用保留在快照中，模型、任务版本、更新时间与实际覆盖仍可见。
旧结果、截断与失败明确显示。手机使用可关闭的客户抽屉。

导航、邮件列表、客户工作区的宽度可拖动并保存。正文自动占据剩余宽度，
不再受 800px 内容上限限制；客户栏可收起恢复，“专注正文”临时收起所有辅助栏，
退出后恢复原来布局。窄屏按实际空间收缩，保持阅读区可用。

正文每封邮件可按需翻译为中文，并切换原文、中文、对照。原文不会被改写；
对照在宽正文中并排、在窄正文中上下排列。翻译只覆盖本封新增正文，历史引用和附件保持原样。
翻译成功后按原文内容与任务版本复用，切换模型不重算，保留实际生成模型署名。

设计验收包括真实 API 配合合成邮件的布局、联系人分组、搜索、列表密度、左右栏操作、摘要来源链接、草稿保持及移动宽度；合成数据不代表生产模型准确率，也不代表服务器已部署。

### 2026-10-09 分栏与原始邮件阅读补充

- 邮箱导航默认 220px、邮件列表默认 360px，继续保留用户已保存的宽度。阅读区最小宽度预算为 360px。
- 导航、列表和客户区统一使用面板间 12px 的整高拖动区域；常态只显示中间的细短握柄，
  悬停、拖动和键盘焦点使用一致反馈。双击或 Home 恢复默认，方向键微调。
- 列表不再用连续蓝色竖线标记线索，保留更小的 SALES LEAD 标签（列表 9px、正文头部 10px）。
- 有 HTML 的邮件从完整 RFC822 原文读取 HTML 正文及 CID 内嵌位图，保留原来的段落、链接、列表、
  表格结构。HTML 在独立的无脚本 iframe 中显示，以 DOMPurify 清除活动内容，CSP 限制外部请求。
  外部图片由用户按封手动加载；内嵌位图自动显示。原始邮件、已存正文、AI 摘要与交易数据不修改。
- 原始 HTML 包含的引用历史完整保留，不再重复追加纯文本引用；纯文本邮件仍保留换行和原有引用折叠。
  HTML 与纯文本统一正文 15px、行高 1.6；邮件纸面保持亮底。

### 2026-10-09 统一阅读排版（用户补充）

保留的是原单词、句子、数字和顺序；呈现统一优化，不照搬发件人视觉样式，不用 AI 重写。
HTML 清除作者样式表、字体、颜色、固定页面/表格宽度和异常留白；保留语义段落、列表、链接、
表格行列及合并单元格、图片、预格式文本、加粗/斜体/删除线等强调。隐藏预览文本保留隐藏状态。
连续空段落压缩成统一间距，数据表格使用细边框和整齐单元格间距，布局表格不误加数据网格。
纯文本按空行建立段落间距，保留原字符、换行与规格列；不会猜测性合并地址、签名或参数行。
正文统一 15px/1.6 行高；脚本隔离、CID 图片与外部图片按封手动加载规则继续有效。
