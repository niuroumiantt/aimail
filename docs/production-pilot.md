# 正式上线与真实邮箱试点

2026-09-20。基于当前仓库检查；这是实施方案，不是已上线能力。

## 当前上线阻塞

- `/design` 是固定样本，与真实数据提供器分离。正式页面只有设置 `VITE_DATA_SOURCE=api` 才读取 API；不能以设计页显示成功作为真实接入证据。
- `api/app.py` 的读信、附件、线索导出接口没有员工认证。`who()` 接受 `X-User` 和 Tailscale 身份头；没有可信入口约束时，头可以伪造。
- 现有多邮箱测试保证服务实例的 mailbox_id 隔离，不代表员工级授权，更不代表跨邮箱检索已经实现。
- `serve` 会启动持续收信、可能调用已配置模型，并接上 SMTP；SMTP 留空会沿用 IMAP 配置。不能靠“不填 SMTP”作为禁止发送措施。
- 现有 ingest 首次会遍历文件夹，尚无限定最近日期、封数的试点模式。不能直接运行安装脚本，它会收信并安装常驻服务。
- 设计审计仅为本地开发服务追加日志，没有可信员工身份、管理员权限或独立防篡改副本。

## 阶段一：单邮箱只读试点

前提：用户确定邮箱/服务商、文件夹、日期与数量上限、允许的模型处理位置。授权码仅写入本机权限 0600 的配置文件，不进入聊天、源码、截图和日志。

建议默认最近 30 天、最多 100 封；IMAP 使用只读选择与 BODY.PEEK，不标已读，不移动、不删信。需先实现有界收取，使用独立试点数据库与游标，不能把筛选后的最大 UID 写进正式全量同步游标。

新数据存于 `~/.local/share/aimail/pilot/`，运行状态/日志存于 `~/.local/state/aimail/`。只绑定 loopback，不开放公网。禁止 SMTP、webhook 和后台全量轮询；API 层也拒绝发送及其他业务写入，不能只藏前端按钮。已有 `mail2leads` 数据目录仅在 Aimail 目录不存在时作为回退；两者同时存在时始终使用 Aimail 目录。

先验证连接、文件夹与收取计数，再导入原文，最后在明确批准的模型后端分析。没有批准模型时只收信，不调用模型。保留示例环境，另开真实试点入口，显著标记数据来源，API 失败不回退成样本。

试点验收：重复收取不重复入库；原文/附件可追溯；旧信阅读不改变最新专题总结；缺失职位/地区不编造；数量变化有出处；所有答案列出实际检索范围与未解析附件。小范围样本只能声称覆盖样本，不得声称已搜索整个邮箱。

## 阶段二：登录、权限与 IT 后台

员工身份从经验证的登录会话取得，不接受浏览器自报姓名。优先复用公司现有身份源，具体接法待确定；安全会话、退出/吊销、CSRF、防暴力尝试与 MFA 策略一起验收。可信代理身份必须限制后端直连并剥离客户端伪造头。

权限按能力与邮箱授权交集计算，而不是只做 admin 布尔值：

| 角色 | 默认范围 |
| --- | --- |
| 员工 | 已授权邮箱的阅读、提问；确认、导出、发送分别授权 |
| 业务负责人 | 被授权团队/邮箱的分配、跟进与汇总；不默认访问所有私人邮箱 |
| IT 管理员 | 用户停用、邮箱连接、权限配置、任务健康与模型配置；不默认读取正文 |
| 审计员 | 受授权审计查询；敏感内容查看/导出另行授权且记录自身行为 |

后台页面：运行概览、用户与授权、邮箱连接、同步任务、模型任务、审计、备份恢复。显示最后成功同步、积压与失败、授权过期、模型耗时/用量、附件解析状态；密码只替换不回显。

跨专题检索先在服务端裁剪用户可见 mailbox_id，再检索与引用。列表、详情、附件、导出、搜索、缓存和模型上下文都应用同一权限；权限撤销后历史对话及引用访问也重新校验。IT 授权变更不能隐式获得客户内容阅读权限。

## 阶段三：正式审计与问邮箱

审计在业务服务端生成：可信 actor、服务端时间、request_id、动作、资源/邮箱 ID、授权结果、成功/失败及必要变更。覆盖登录、读信、附件访问、提问/答案引用、清屏、新会话、导出、确认、发送、权限与设置变更，以及拒绝访问。

浏览器点击日志只能作为体验诊断，不能证明业务操作成功。不要记录密码、令牌或每次按键；对话正文作为受控会话数据保存，审计以引用关联，避免每次点击复制邮件内容。

清屏只更新显示游标，旧会话保留在服务端；新会话另建 ID。重载、换设备可查历史。先保存再确认清屏。审计落盘失败时敏感写操作拒绝执行；其余失败策略需明确，不可静默丢日志。

业务变更与审计在同一事务写入，外部发送/推送记录准备、结果与不确定状态以便核对。数据库禁止应用更新/删除审计；追加独立受限存储副本与告警。数据库管理员仍能修改本机文件，不能把 SQLite 触发器称为完全防篡改。

真正问邮箱需要版本化模型任务、评测集、权限内检索和可点击来源；当前关键词演示不得直接充当生产 AI。邮件与附件均是不可信输入，其内嵌指令不能修改权限、触发发信或绕过审计。

## 开放给员工前的门槛

- 匿名与伪造身份无法读取；员工 A 无法猜 ID 访问 B 的邮件、附件、会话或导出；管理员无内容授权不能读正文。
- 清屏、新会话、刷新后审计仍可查；审计失败路径测试通过；审计员的查询/导出也留痕。
- 有界试点、实际模型评测、真实同步断线续传、权限撤销测试通过。
- TLS、网络访问范围、密钥管理、日志脱敏、用户操作告知、数据保留周期明确。
- 完成独立备份及恢复演练；升级可回退，原文数据不随代码回退删除；同步和模型失败可告警。
- 先向自己发送测试信需用户单独明确确认收件人和内容；之前始终关闭发送。

待用户确定：试点邮箱与收取范围；公司身份源与首位管理员；部署机器/访问范围；允许的模型后端；审计正文访问与保留策略。

## 已确认方向：网易 sales 邮箱与 Spark API

用户指定 `sales@glocalstorage.com`，网易邮箱；首个模型后端使用公司 Spark 本地模型 API。后续替换 API 由 IT 后台控制，不要求前台修改配置。收取范围暂按最近 30 天、最多 100 封的试点建议，尚未执行真实收取。

OA 只读检查依据：`apps/mail/receive.py` 使用只读 IMAP，口令由 `credential_env` 引用部署环境；`keel/aitask.py` / `docs/adr/0031-bounded-ai-task-gateway.md` 定义任务网关；`docs/reviews/2026-09-04-qwen27b-real-mail-baseline.md` 有真实邮件受控评测。OA 的网关文档明确计费/用量账本尚未实现。复用接口理念及已批准配置，不 import OA 业务包，不修改 OA 数据。

后台划分两个独立配置区：

- 邮箱连接：协议、服务地址、端口、账号、凭据引用、文件夹、同步范围/频率、连接测试、最后成功时间。当前已知代码为 IMAP，并无已验证的网易 HTTP 邮件 API。
- 模型连接：连接名称、API 类型、固定服务地址、凭据引用、模型/路由、超时、并发、重试上限、预算与启停状态。可测试连接、保存草稿、评测后启用和回滚；不允许浏览器提交任意 URL 让服务器代理访问。

前台提交固定业务任务（读信、专题总结、跨专题问答、起草），由服务端映射至已批准连接。切换不改变前台合同；模型身份、任务版本和生成时间仍保存在结果署名中，不能为隐藏配置而丢弃出处。切到外部供应商须单独批准数据出域，不自动回退到外部 API。

用量账本每次调用尝试一条，包括失败与重试：request/task/attempt ID、可信用户、邮箱范围、连接及配置版本、实际返回模型、任务版本、开始结束时间、排队/调用/总耗时、状态/错误类型、上游 request ID、输入/输出/缓存 token（支持时）。上游未返回的用量标记未知，不能记成 0；请求耗时不能冒充 GPU 占用时长。

价格规则按供应商协议配置 token、请求或时长等计费方式，记录币种、单价、生效时间与调用当时的价目快照。费用分为供应商报告、规则估算和未计价；Spark 无按次账单时标为内部算力，可另配内部核算费率，不声称运行免费。多币种分开汇总，失败调用也可能收费，不得排除；后续账单对账避免网关与上游重复计费。

后台统计按日期、用户、邮箱、任务、连接/模型聚合调用量、成功率、重试率、token、总耗时、P50/P95 延迟及费用；展示未知用量数量和估算占比。预算超限由服务端限制，不仅前端提示。连接/费率/路由变更均留审计，历史成本不随今日改价重算。

## 已实现的独立命令行试点

`python -m aimail.pilot --mail-config <私有配置路径> --mailbox <明确邮箱> --limit 10`

配置文件作为数据解析，不执行 shell；只读 INBOX，最多最近 30 天/100 封，默认 10 封，每封最大 2 MB。独立数据库 `~/.local/share/aimail/pilot/mailbox.sqlite3`，不写 OA 数据、不更新正式同步游标、不启动网页/SMTP/webhook/轮询。超过上限明确计数，不称为已完整读取邮箱。暂不支持跨文件夹覆盖。

`python -m aimail.backends.pilot --config <Spark配置路径> [--endpoint <核实后的内网端点>]`

独立读取最新一封已收邮件的正文，复用现有版本化摘要合同、结构化校验和数字核对；暂未覆盖附件或跨邮件综合分析。结果保存到同一私有目录的 latest-reading.json，用量记录到 model-calls.jsonl，包含失败、耗时、实际模型、token 和未计价标记；不是正式管理员账本。无外部模型回退。结构化校验通过不等于语义准确率通过。

2026-09-20 首次真实收信：选中 10 封、保存 9 封、1 封超过大小上限跳过。网易只读连接成功。OA 留存的 Spark 旧地址超时；通过 infra 文档与 Tailscale 当前在线节点核实新地址，并仅给独立试点传入覆盖值，未修改 OA 配置。

## 公网裁决

### M5 本地 openapi 接入

`tools/configure_local_api.py` 为 Aimail 申请独立 100,000 点模型受限 Key，
以 0600 权限保存于 `~/.config/aimail/local-api.env`，不在源码或日志回显。
已有配置拒绝覆盖。执行 `python -m aimail.backends.pilot --config <该配置>`
经本机 8800 网关而不是直接访问 Ollama；不会调用 Spark 或修改 OA。

openapi 为独立仓库 `~/code/openapi`，持有自己的调用与正文记录数据库。
用户已要求观察 Aimail 的 API 对话，因此网关显式为 aimail 标签开启正文记录；
管理页可按调用查看实际发出的上下文与回答。该功能不代表 Aimail 前台问邮箱已接通，
也不代表跨邮件检索与完整会话管理已经完成。

可以建设公网入口，但当前版本不满足公开部署条件，本次没有发布或开放端口。

推荐公网 HTTPS 反向代理 / 身份入口 → 应用服务 → 私网 Spark；浏览器只访问应用，不持有邮箱密码或模型密钥。只公开 443，应用源站限制到反向代理，数据库、模型 11434、开发服务器 5197 和网关端口不公开。即使有边缘登录，应用仍须验证可信身份并执行每条记录的邮箱授权。

公开部署前需完成：可靠登录与 MFA/会话吊销、默认拒绝的员工/邮箱授权、CSRF、请求/附件大小上限、用户并发与调用预算、后台凭据管理、审计权限、供应商端点限制（防 SSRF）、监控与备份恢复。真实试点库不能打进镜像或部署包，开发调试栈和示例模式不能冒充生产界面。

上线顺序：单人内网只读验收 → 少量员工内网试用与越权攻击测试 → 确定域名/部署机器/身份源后发布公网。公网部署及修改现有反代、防火墙、OA 网关不在本次试点中执行。
