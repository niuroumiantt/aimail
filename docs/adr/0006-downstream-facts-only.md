# 0006 下游只看事实:版本化只读接口 + 签名推送

日期:2026-09-19 · 状态:已采纳 · 依据:CONSTITUTION.md 第五、六条;docs/api/v1.md

## 决定

- 下游(OA、PO、合同)只通过 `/v1/*` 拿线索,拿到的只有 `lead` 表——人确认过的事实。`lead_suggestion` 不出门。
- 机器身份是 Bearer 令牌(`API_TOKENS`),**只能读**;写线索的接口只认人的身份(tailscale 登录名 / X-User)。
- 接口版本化两层:路径 `/v1` 和对象 `lead@1`。形状钉死在测试里的键表;改字段 = 新 ADR + 新版本,旧版本继续服务到下游迁完。
- 推送走发件箱:写线索的同一个事务里记事件,后台按退避投递,HMAC-SHA256 签名,`X-Mail2leads-Delivery` 让下游幂等;
  失败记原因、永不丢、界面可见。配了 URL 就必须配密钥。
- 游标是 `(updated_at, id)` 一对,不是单个时间戳:同一秒确认的几条不会漏。

## 为什么

- 建议是模型的,事实是人的;下游系统要开 PO、签合同,拿到一条没人确认的建议就是事故。
- 令牌只读是最小权限:泄露一个令牌最多泄露线索,不会凭空多出「已确认」的线索。
- 版本钉死在测试里,才能保证「接口变更走 ADR」不是一句空话——改了键表 CI 就红。
- 发件箱比「确认时直接 POST」可靠:下游挂了不影响确认,事件不丢,重试有节奏,而且送没送到有账。

## 否决了什么

- 让 OA 直接读 SQLite 文件或数据库:绕过身份与版本,表结构一改下游就断,也违反「只借资源不受指挥」的边界。
- 不签名的 webhook:下游没法信;只用 IP 白名单在 tailnet 里也不够,密钥是最小成本。
- 推送建议(未确认)给下游「先看着」:见第一条,建议不是事实。
- 时间戳单游标:同一秒多条会漏。

## 推迟了什么

- 反向写入(OA 把 PO 号、合同状态写回线索):等 OA 那头真的接上了、看到真实字段再定,届时仍是人的身份或专门的写令牌。
- 令牌轮换与过期:先靠部署机的环境变量与 0600 权限;有第二个下游再做。
- 跨邮箱的下游视图:等 M9。
