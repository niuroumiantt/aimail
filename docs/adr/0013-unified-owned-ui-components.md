# 0013 统一自有 UI 组件

日期：2026-10-09 · 状态：用户已选定；页面迁移尚未完成。

## 决定

Aimail 全站采用 React + TypeScript、自有组件、Radix 行为原语和 Tailwind v4。
以用户提供的 Outlook Mac 截图为收件箱布局基线，所有业务页复用同一套页面框架和组件；Ant Design
是迁移中的既有依赖，逐页移除，不再作为另一套长期组件方案。图标统一使用 Lucide。

借鉴 shadcn/ui 的自有组件组织方式；不导入另一套默认主题，也不切换框架。
业务交互、数据模型和邮件工作流保持由 Aimail 自己管理。

## 唯一现行视觉规范

- 颜色沿用生产收件箱：冷白表面、slate 中性色、indigo 操作与选中强调；状态色只表达状态。
- 字体使用自托管 Inter / Noto Sans SC；金额、型号等使用现有等宽与数字对齐规则。
- 字阶为辅助 12px、正文 14px、邮件原文 15px、栏标题 16px、页面标题 20px。
- 间距以 4/8px 为节奏；控件高度 36px、小控件 32px；控件圆角 8px、面板圆角 12px。
- Lucide 常用 16/18px、线宽 1.75；图标按钮具备可访问名称，常规操作保留文字。
- 收件箱采用品牌色全局搜索栏、集中邮件工具栏、应用图标栏、邮箱视图、紧凑列表和独立阅读面板。
  列表默认宽度 420px，显示圆形联系人头像、发件人、主题和单行 AI 摘要；按会话更新时间分组。
  阅读区保留一次主题与每封信的发件信息，来信原文使用平整表面；客户工作区初次默认收起。
- 2026-10-09 用户参考线索页进一步要求大区域独立成面板：工具栏、应用栏、邮箱视图、列表、
  正文与客户区分别使用统一的 12px 圆角、轻边框和轻阴影，桌面间距 12px、手机间距 8px。
  导航浅灰、列表偏冷浅色、原文白底、客户上下文淡蓝灰；对应的亮暗面板色统一定义在 theme.css。
  区域内部保持紧凑，不把每封邮件或每段原文继续拆成嵌套卡片。
- 配色、字体和亮暗模式由 `web/src/tokens/theme.css` 提供；应用尺度与共享样式由
  `web/src/tokens/design-system.css` 提供。`outlook-workspace.css` 提供收件箱布局，不另建配色或字体。

2026-10-09 用户随后提供 Outlook Mac 截图，布局基线据此调整；继续使用 Aimail 品牌和语义色。
不恢复早期 sage/teal 配色。ADR 0004 的颜色选择及早期
`docs/design/landscape.md` 的配色结论是历史记录，由本决定取代；字体仍遵循 ADR 0007。

## 组件和页面边界

页面只组合共享组件。按钮、输入、选择器、弹窗、菜单、提示、标签、列表、空状态、
加载与失败状态使用同一套定义；Radix 提供焦点管理、键盘操作和交互原语，视觉由自有组件控制。
所有生产业务页共用 AppShell、导航、邮箱与模型选择器、主题切换和页面标题层级。

`/kit` 是现行组件与状态的对照页。`/design` 和 `/design/inbox` 为设计实验，
保持实验标识和独立样式范围，不从业务导航宣传为正式 UI，不作为第二套业务入口。
旧 `/mail` 在生产仍跳转正式收件箱；不得为修视觉而绕开其既有收口条件或删除未迁移能力。

## 迁移顺序和验收

1. 补齐共享表单、选择器、弹窗、状态提示与空状态，在 `/kit` 展示键盘、禁用、加载和失败状态。
2. 先迁移 `/followups` 的 Ant 控件和详情，再核对 `/outreach`、`/leads` 与收件箱的相同交互。
3. 收口旧试点及实验中的 Ant 引用；确认能力归属后移除相关主题适配和 `antd` 包依赖。

每批保留原有 API、身份权限、交接、草稿和人工发送授权；迁移须通过完整 precommit
及实际浏览器检查。检查亮暗、桌面与窄屏、导航与弹窗键盘焦点、密度和文字层级。
只统一颜色或替换包依赖不算完成；验收需以各业务页面和控件状态的截图对照为依据。
在所有 Ant 引用与依赖移除、业务页对照检查通过前，不宣称全站统一已经完成。

## 为什么

共享颜色和尺寸不足以统一两套组件的结构、交互和状态。当前收件箱已有自有组件基础，
沿用它并收口跟进页，比继续维护两套组件更容易保持一致，也符合 ADR 0002 的既有方向。
