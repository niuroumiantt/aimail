# 0012 — 邮箱模型选择只影响后续任务

本文取代 0010 中模型参与缓存指纹的部分，其原文来源、权限和独立话题边界继续适用。

## 决定

每个可访问的完整邮箱保存一个模型后端选择：`local`、`codex_cli` 或
`claude_code_cli`。`GET /api/model-selection` 返回当前选择、模型署名和三个节点能力；
`PUT` 使用 `{selected: ...}`，要求人的身份、完整邮箱访问权限及所选后端当前可用。
不可用时明确失败，不保存选择，不回退到另一个模型。

保存选择仅更新邮箱偏好，不检索邮件正文，不生成分析，不触发历史重分类。
没有保存选择的旧部署沿用环境里的后端默认值，独立研发 CLI 命令仍有效；旧
Anthropic API 默认值不等于 Claude Code CLI，也不能冒充后三者之一。

原文自动分析使用其邮箱保存的后端；用户在已授权邮箱中主动发起分析、起草或助手
问答时使用当前选中邮箱的后端。每次任务捕获一次选择并用上下文变量作用域执行，
不修改进程环境变量。摘要、采购建议与失败记录在同一任务作用域中署名。
异步客户摘要任务在排队时捕获后端和实际型号，工作线程显式恢复这个作用域；排队后用户改变
偏好不会给旧任务贴上新后端署名，也不会影响其它线程、邮箱或用户。

界面的「重新分析」是明确的单封重算，原文不变，新增一条派生读数。重复点击仍是
用户明确操作，不扩展到其它邮件。历史维护入口继续要求显式 `--apply` 和有限预算，
整批固定一个后端快照；不会因为选择变化重新处理已有当前版本的读数。

## 客户需求摘要复用

需求摘要的身份由邮箱、独立话题、联系人、全部原文与附件提取清单、摘要任务版本、
视图版本、问题及输入预算决定，**不包括所选模型**。相同输入已有成功摘要时，即使
模型换了，或传 `retry=true`，仍复用成功摘要，保留当时的模型、任务、时间和来源。
失败重试是显式操作，不是“换了模型就把联系人历史重新读一遍”。

旧 `customer_workspace@1` 把模型写入指纹。读取旧缓存时，按缓存记录自己的模型署名
重建旧指纹，与当前原文输入对照；匹配即复用，不改写旧署名，不调用模型、不批量
迁移历史记录。旧版运行中的同内容任务也阻止重复排队。

新来信、我方发信、补入历史原文或附件提取结果变化会改变该独立话题的输入；其它
话题和邮箱不失效。摘要任务／视图合同或问题、预算变化仍会失效，以免复用不满足
新合同的旧结果；这与模型切换不同，只在访问该联系人的摘要工作区时处理。
刷新失败时旧摘要保留并标为过时，失败状态显形，不用空白代替成功结果。

## 验证边界

测试覆盖选择持久化、零模型调用、不可用不保存、邮箱权限隔离、旧指纹兼容、
无变化复用、只更新有新内容的话题、后台任务作用域、失败署名与主动单封分析。
这些是路由／存储合同测试，不代表任一 CLI 已登录连通，也不代表 Spark 分类准确率。
节点能力说明只能报告配置与当前可见能力；真实推理失败仍须显形。
