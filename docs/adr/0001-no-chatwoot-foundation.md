# 0001 不用 Chatwoot 做地基

日期:2026-09-19 · 状态:已采纳

## 决定

收信、发信、线程归并、存储、界面全部自己写。
Chatwoot 只作参考:它开源(MIT),色板、间距、空状态插画、组件写法,
好的抄进我们的树(带署名),不 import 它的包,不跟它的发布节奏。

## 为什么

上周选 Chatwoot 是为了省一套收发信和界面。现在界面自己做(ADR-0002),
它剩下的价值是 IMAP/SMTP 和线程归并——约一两千行 Python,边界清楚。

代价是自己写这些。换来:不跑 Rails + Postgres + Redis + Sidekiq 四个进程,
不用 iframe 面板,不用防 webhook 自激循环,数据模型是自己的。
以 AI 为地基的系统,主对象是「邮件 + 读数 + 线索」,不是「分配给客服的会话」。

## 否决了什么

继续在 Chatwoot 上搭,我们的界面通过它的 API 读写。
否决理由:它的会话模型会成为我们的地基,升级节奏跟它走——这正是宪法第八条说的「靠」。

## 推迟了什么

无。

## 后果

- M2 要自己写 IMAP 收信、MIME 解析、按 Message-ID / In-Reply-To / References 归并线程
- M5 要自己写 SMTP 发送并带 In-Reply-To 头
- 已有的 mail-agent 原型里,Chatwoot 客户端与 webhook 部分作废;
  任务合同、核对器、后端适配器、52 个测试在 M3 搬入
