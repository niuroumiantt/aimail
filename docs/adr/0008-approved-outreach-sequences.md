# ADR 0008：固定内容、人工批准的开发信序列

2026-09-23。按拥有者明确要求，外部公开业务名单进入 prospect，而非人工确认的商机表。
宪法第二条已单独修订；即时回复继续使用原一次性令牌。

## 决定

名单接口专用令牌只能导入、读事件和停发，不可批准。`/outreach` 提供人工确认页面，
批准绑定收件邮箱与六封完整标题/正文哈希，固定日期 0、7、14、28、60、90。
变更内容必须新的明确决策，本版不提供自动重启或复制序列绕过去重。

后台只有成功完成最新 IMAP 同步后才检查到期项。发送总开关默认关闭。
SMTP 前持久化 MIME、Message-ID、attempt；遗留发送尝试或任何不确定结果停止并等待核对。
唯一标识不保证 SMTP 幂等，故不通过自动重试追求假“恰好一次”。
停机错过多个节点仅执行最近到期的一封，跳过旧节点并保留事件。
默认 20 次/UTC 日是保护性上限，不是营销政策或送达保证。

## 稳定代码判断，而非语义推断

邮箱精确匹配、Message-ID/References、标准 MIME delivery-status 的 Final-Recipient/Action
均是协议/身份字段，不是意图分类。任何来信都保守停止，包含自动回复或退订请求；
不使用“谢谢”“退订”等关键词模拟语言理解。DSN 失败停发，延迟 DSN 先暂停。
邮件语义、买卖方身份和意图仍归原有版本化任务，本模块不新增长篇模型判断。

## 约束与上线门槛

- 一邮箱一 poller；同邮箱内按公司幂等键、邮箱与 external_id 三道去重。
- 没有跨发件邮箱的组织级去重，当前不可多实例并发投放同一名单。
- 真实发件地址、SMTP/IMAP 凭据、地区政策和六封内容需单独核验；未批准名单不会发送。
- 代理负责可信 OA 身份，另注入 `OUTREACH_APPROVAL_PROXY_KEY` 对应的 `X-Outreach-Approval-Key`。
  代理必须删除浏览器自带的同名头再注入密钥；导入调用方不持有此密钥，不能从内部网络伪造人工批准。
  发件地址也绑定内容哈希，更换发件身份会暂停而不是沿用旧批准。
- 只新增表，不改原始邮件、商机或已有数据。部署前备份现有 SQLite。

验证见 `server/tests/test_outreach.py`；真实客户发信不作为自动测试的一部分。
