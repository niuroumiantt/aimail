# 0002 React + Tailwind v4 + 三条规则

日期:2026-09-19 · 状态:已采纳

## 决定

框架 React(Vite + TypeScript)。样式 Tailwind v4,外加三条规则:

1. `@theme` 只定义我们的语义令牌,Tailwind 默认色板一个颜色都不留
2. 禁任意值 `[…]`,守卫 grep
3. 视觉样式只写在 `web/components/`,`web/pages/` 只用布局类

组件行为用 Radix,按 shadcn/ui 的写法复制进我们的树——借,不靠。

## 为什么

样式方式不决定好不好看:Radix Themes(纯 CSS)与 shadcn/ui(Tailwind)都精致。
决定的是工作流。写代码的主要是 AI 协作者:Tailwind 写对率最高,且不用起名——
命名恰恰是 AI 最容易起得平庸、前后不一致的地方。shadcn/ui 的「复制进自己的树、不依赖」
正是宪法第八条。尺度由构造保证,不靠事后 grep。

关默认色板,是因为发起人明确不要一个全网一样的配色。
大多数 Tailwind 项目看着廉价,不是 Tailwind 的错,是没关默认色板。

## 否决了什么

- Vue:能原样抄 Chatwoot 组件,但无头组件生态薄一档,且我们要抄的主要是数值不是组件
- Svelte:生态小,无头组件库还年轻
- 纯 CSS 变量 + CSS Modules:可读性更好,但命名成本与漂移风险在小团队更贵。
  若日后更看重「任何人打开 .css 就能读懂」,这条可以翻
- CSS-in-JS:运行时开销,已在衰退

## 推迟了什么

令牌具体数值、字体配对、图标集、组件清单——M1 横评后定,各自写 ADR 或进 `docs/design/`。

## 后果

M0 的守卫要包含:禁任意值;`pages/` 禁颜色、圆角、阴影类;令牌文件之外禁字面色值。
