# 0009 会话授权绑定来源分配版本

日期：2026-10-03 · 状态：已采纳 · 依据：CONSTITUTION.md 第一、三条及 ADR-0006 的接口版本约定。

## 决定

- 新增 `POST /v2/followups/access`，保留 v1 请求与回执形状。v2 要求正整数
  `assignment_version`，它来自客户工作台已经接受的分配事件，独立于邮件侧 `version`。
- 同一 `external_id` 和线程只接受更大的来源版本；同版本同负责人幂等，同版本不同
  负责人及旧版本拒绝。来源版本写入原有追加式授权事件，重启后仍有效。同一负责人
  接受新一轮分配也必须留下新来源版本。
- 先升级邮件服务，再升级客户工作台。旧 v1 可操作尚未收到版本化授权的会话；
  一旦启用 v2，v1 不得覆盖这个会话。回滚旧客户端会得到冲突，不能静默解除版本保护。
- 客户工作台把来源版本保留在同步队列，确认成功或安排失败退避时均比较请求快照，
  旧回执不触碰新队列。新客户端不接受缺失或不匹配来源版本的回执，也不回退到 v1。
- 已有队列升级后，取最后一次对应负责人的接受事件版本并重新同步一次，建立远端
  版本保护；不使用尚未接受的转交提议版本，不重放内部通知或发送客户邮件。
- 权威仍来自最初的集成授权事件，不由用户填写的 note 冒充。授权始终只针对一个会话。

## 跨邮箱回复的处理

个人邮箱收到、经既有严格归并规则关联到共享会话的来信，保留真实 message.mailbox_id。
读数仅使用这封信及其附件，不把共享或个人邮箱的其它客户会话扩大为模型上下文。
普通同邮箱来信继续使用原有客户历史。发送及人工核对按确切 thread-message 关联
保留回复原件与审计；核对不调用 SMTP，也不放松当前负责人、一次性令牌和证据要求。

## 否决与推迟

- 否决只在客户端忽略旧回执：远端仍可能被迟到请求恢复成前任负责人。
- 否决只比较负责人地址：A→B→A 的旧回执会与新负责人同名，仍须版本。
- 否决为旧回执自动降低接口版本、开放整邮箱历史或凭 Message-ID 全库核对。
- 推迟跨服务原子事务和全局员工权限重构；本次保持来源权威、持久队列及幂等合同。
