# 0003 SQLite 起步

日期:2026-09-19 · 状态:已采纳

## 决定

SQLite(WAL 模式)起步,FTS5 做全文搜索。

迁移触发条件写死:出现第二个写进程,或单库超过 10 GB。触发即开 ADR 迁 Postgres。

## 为什么

一个文件、零运维;一个共享邮箱的全部历史装得下。

## 否决了什么

一开始就 Postgres——多一个进程、多一套备份,v1 换不来任何东西。

## 推迟了什么

Postgres。触发条件到了再迁,不提前。

## 后果

- `store/` 用参数化 SQL,不用 ORM 特性把自己绑死在 SQLite 上
- 原文表的只读约束用触发器实现(宪法第三条)
- schema 从第一天带 `mailbox_id`(多邮箱是配置不是重构)
