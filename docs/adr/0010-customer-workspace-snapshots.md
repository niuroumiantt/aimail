# 0010 客户工作区的显示快照

2026-10-04。用户选定联系人聚拢、右侧独立需求摘要和无新内容时复用。

联系人范围是当前获授权邮箱内的精确规范化地址，包含来信与我方回复。
不同邮件线程分别展示，不用公司域名把不同联系人混在一起，不自动合并独立交易。
关闭聚类、搜索、切换列表密度和阅读旧信只影响浏览，不改变摘要范围。

复用 `ask_mailbox@1` 的来源引用与数字核对合同，每个话题从不可变邮件原文和
确定性附件提取文本生成累计结论。新增的显示快照不成为客户事实，不喂给下一次模型；
ADR-0005 的原文作为唯一模型依据继续成立。客户档案仍使用已有联系人信息，模型
结论全部注明待核对、模型、任务版本和更新时间，保留来源证据。

同日阅读布局迭代：客户工作区只展示当前选中话题的客户资料和最新累计生意概况，
GET 和 POST 都限制在这个话题；同一客户的其他话题不会因打开当前话题而触发分析。
按用户要求，右侧不再放逐点原文链接、往来时间线和单封读数；原文仍在正文阅读区，
快照中的原文引用和来源 ID 保留，验证合同不变。

输入指纹包含邮箱、联系人、线程、所有原文 ID 与哈希、附件字节哈希与提取状态／版本／文本、
任务版本、问题及读取预算。模型路由不作为内容失效条件，保留成功结果的原始模型署名。
没有变化时复用持久快照，模型调用为零；新增旧日期的
来信、我方新回复或附件提取变化也会使相应话题失效，其他话题结果保留。
GET 只读取；POST 根据指纹声明任务，唯一键与有期限的执行声明阻止并发重复。
模型在后台的独立数据库连接运行，不阻塞正常邮件阅读。

每个话题输入最多 60,000 字符，优先保留最新原文。界面明确显示覆盖、截断和未读附件，
不把有限输入称为全部读完。失败保留上一次成功结果并显示过期与失败，普通刷新不重试
同一失败输入；用户点击更新可明确重试。授权仍在每次请求检查，不提供跨邮箱客户接口。

部署维持现有 Spark／HTTP 模型后端；这次没有引入 Superhuman 私有 API，也没有切换
生产服务器的模型或自动重算全部历史分类。`business` 和历史询盘在线程层保持商业信号，
显著显示 SALES LEAD；供应商推销等分类质量仍需后续真实样本评测。

验收包括无变化与重复邮件零调用、历史补入、新发回复、附件变化、并发去重、重启复用、
独立话题隔离、失败显形、跨邮箱拒绝和后台模型等待时继续阅读。合成样例的引用合同基线
在 `evals/ask_mailbox/`；合成／mock 检查不代表真实 Spark 模型准确率。
